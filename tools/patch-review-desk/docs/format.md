# Input and persistence contract

Accepted input is UTF-8 (strict decoding) with Git `diff --git` file sections, LF-delimited patch records, extended headers, `---`/`+++` paths, and ordinary `@@ -start,count +start,count @@` hunks. A missing count means one; zero-length ranges are supported. Source CR bytes are preserved as source characters, not normalized. NUL input is rejected. A UTF-8 BOM is retained and flagged as unparsed content, not stripped. A patch without its transport-final LF is flagged as potentially truncated; this is distinct from a source missing its final newline.

The parser retains each file-section header and metadata, each ordinary hunk, each source row and its patch-line location. It counts old/new consumption independently and warns on mismatches, excess rows, zero-based nonempty ranges, or overlapping/out-of-order hunks. File additions/deletions use `/dev/null`; renames/copies and mode-only changes appear as metadata. Git C-quoted paths decode escaped characters and three-digit octal UTF-8 bytes. Ambiguous unquoted headers are flagged; explicit old/new markers and rename metadata provide paths when available. A `\ No newline at end of file` marker attaches to the preceding source row without consuming a source line.

Binary differences retain metadata with a visible content-unavailable warning. Git binary payload records, combined diffs (`diff --cc`, `diff --combined`, `@@@`), submodule mode 160000, email preambles/trailers, non-Git diffs, and unrecognized metadata generate warnings. They remain in original bytes; they are not a supported rendering of those formats. All `diff ` sections count toward file accounting, including unsupported formats. A malformed hunk header remains visible in metadata with a warning; it is not counted as an interpreted hunk. Text hunks missing old/new file markers are flagged. Warnings refer to original patch line numbers.

“All sections parsed within the supported subset” means no parsing warnings, not that the patch applies to a repository, that source outside the patch is available, or that a supplied revision claim is authentic. The application does not access remote repositories. Imported provenance is displayed as **supplied metadata**. The bundled demos have separately reproducible and verified provenance.

# Identity and recovery

A project is `patch-review-desk/1` JSON with SHA-256, base64 original bytes, name, optional source metadata, notes, reviewed flags, and a derived parsed view. Import ignores the supplied parsed view and recomputes it. Notes are keyed by file-section ordinal, hunk ordinal, and source-row ordinal. Reviewed flags are keyed by file or hunk ordinal. These identities are meaningful only within the exact patch hash. Duplicate basenames and repeated hunks have different identities, even if overlapping ranges produce warnings. Changed bytes or invalid note/status identities reject transfer.

One active workspace is saved in browser localStorage after every saved note/status/import. Recovery checks the hash before displaying it. LocalStorage is origin-specific and may be cleared, unavailable, or too small; failed saves are announced. JSON export is the durable transfer mechanism. Do not rely on localStorage as your only backup. File and hunk review flags are intentionally independent.

# Offline exports and privacy

JSON includes original bytes, provenance, displayed changes, notes, review status, and coverage warnings. Standalone HTML includes the same information and a visible, escaped JSON block containing the original bytes for recovery. Both may contain confidential patch contents and notes. Source strings and all imported metadata are rendered through DOM textContent or HTML escaping. The HTML report has no JavaScript and a restrictive content security policy forbidding network resources. The application requests only its own local assets and bundled demos. Source URLs are text references and are never fetched. Browser extensions and the browser's own background traffic are outside application control.

Resource bounds are enforced before replacing the workspace. The derived portable project must also fit within 8 MiB (with space reserved for review flags); an unusually escape-heavy patch can exceed this bound even when its input is below 1 MiB. A note that would exceed this bound is rejected without changing the saved note. The server is a local static server; use it on loopback, not as an internet-facing service. Imported source is never evaluated, imported as a module, or passed to a shell.
