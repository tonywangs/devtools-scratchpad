# Import and timing semantics

Based on the [HAR 1.2 specification](https://www.softwareishard.com/blog/har-12-spec/) and its [historical draft mirror](https://webperfwg.org/specs/HAR/Overview.html). The mirror is abandoned and is not a current W3C Recommendation. Existing implementation studied: [Jan Odvarko HAR Viewer](https://github.com/janodvarko/harviewer).

The importer requires a 1.2 log and entries array. Every original array position becomes a 1-based ordinal, preserved after chronological sorting. Missing/invalid URL or method strings or status outside integer -1..599 is explicitly rejected. This is a supported inspection subset, not exhaustive HAR schema validation. Missing timing fields do not reject otherwise inspectable requests. Status 0 and Playwright's -1 are failed/no-response sentinels, not HTTP codes. Redirect entries remain distinct and targets are text only. No redirect chain is inferred.

Timestamp input must include date, time and explicit Z/offset. Invalid calendar days are unknown. JavaScript Date.parse resolves offsets and truncates submillisecond precision; leap seconds are unsupported. Unknown starts sort last, ties retain ordinal order. Malformed page metadata is ignored; an entry with no matching page goes to Unassigned. Duplicate page IDs group together. Page event timings remain available in the original HAR; the viewer does not equate them with perceived load.

Finite nonnegative timing values are known; negative, missing or nonnumeric fields remain null/unknown. Available segment sum = blocked + dns + connect + send + wait + receive, omitting unavailable fields only from this sum. SSL is shown as a subduration of connect and never added again. SSL greater than connect, or SSL without connect, is flagged. Available phase totals differing from entry.time by more than max(1 ms, 0.1%) are flagged; with missing phases, this indicates incomplete evidence and does not prove producer error. Values are not rescaled to force agreement.

Summed known duration adds entry.time for all selected known durations, including overlapping requests. Known activity spans earliest start to latest start+duration among selected entries with both values. Unknown durations and excluded bounds are counted. Neither is a measure of perceived page load. Waterfall bars use reported duration and start; the details list phase durations separately to avoid inventing offsets for unknown phases.

Response bodySize is shown when nonnegative, otherwise unknown. It is not total transferred size. Cache objects, 304 status and producer `_fromCache` indicators are displayed as evidence, not a definitive cache classification. A 304 does not imply zero transfer.

Files above 10 MiB or 10,000 entries reject wholesale; smaller incomplete imports expose every rejected ordinal. No silent subset. Rendering uses textContent, escaped script-free reports and restrictive CSP. Project notes are capped at 20,000 characters each. Current filters determine exported requests; full-import accounting and source hash remain in every report. Unknown fields persist in original-entry inspection, but diagnostic exports intentionally omit raw headers/bodies and are not lossless HAR replacements.
